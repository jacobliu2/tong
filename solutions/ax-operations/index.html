홈 / 문제별 해법 / AI·DX 업무 운영체계 전환

AI와 DX로 업무 운영체계를 바꾼다는 것은 무엇인가

요약

AX(AI 전환)는 AI를 쓰는 것이 아니라 업무 흐름을 다시 설계해 병목을 줄이는 것입니다.
도구를 먼저 고르지 않고, 반복되는 수작업과 정보가 끊기는 지점을 찾아 업무를 다시 설계한 뒤, 이미 있는 도구로 해결할 수 있는지부터 확인하고 필요한 경우에만 만들거나 도입합니다.

01어떤 기업의 문제인가

직원들이 개인적으로 AI를 쓰고 있지만 회사의 업무 방식은 그대로인 회사입니다.

여러 프로그램을 쓰는데 같은 정보를 여러 번 입력하는 회사, 수기와 엑셀 정리에 시간이 많이 드는 회사, 디지털 전환 지원사업을 검토하면서 무엇을 바꿀지 정리가 필요한 회사가 해당됩니다.

02이런 증상으로 나타납니다

  • 시스템이 있는데도 엑셀이나 수기로 다시 정리합니다.
  • 같은 정보를 두 곳 이상에 입력합니다.
  • 쓰는 프로그램은 늘었는데 업무 시간은 줄지 않았습니다.
  • AI를 쓰는 직원과 안 쓰는 직원의 업무 방식이 완전히 다릅니다.
  • 회사 자료를 외부 AI 서비스에 넣어도 되는지 기준이 없습니다.

03가능한 원인

도구에서 출발했습니다

어떤 업무의 어떤 병목을 줄일지 정하지 않고 도구를 고르면, 도구에 맞춰 일이 하나 더 늘어납니다.

업무 흐름은 그대로 두었습니다

기존 절차 위에 자동화나 AI를 얹으면 개인의 속도는 빨라져도 회사의 흐름은 바뀌지 않습니다.

데이터가 쌓이는 규칙이 없습니다

도구마다 정보가 따로 있고 입력 기준이 다르면 AI가 활용할 데이터도 쌓이지 않습니다.

사용 원칙이 없습니다

어떤 데이터와 판단을 외부 서비스에 맡기고 무엇을 회사가 통제할지 정하지 않으면 도입이 불안해지거나 무분별해집니다.

04컨설팅에서 진단하는 것

  • 현재 디지털 수준 (DX 7단계)과 AX 준비도
  • 반복 업무, 수기 관리, 중복 입력이 일어나는 지점
  • 업무별 소요 시간과 병목
  • 현재 쓰는 도구와 그 연결 상태
  • 데이터·판단을 외부에 맡기는 범위 (기술주권·사유주권)

05개선은 이 순서로 진행합니다

  1. 병목 찾기

    업무 흐름을 따라가며 시간이 가장 많이 들거나 정보가 끊기는 지점 두세 곳을 고릅니다.

  2. 업무 재설계

    그 지점에서 꼭 필요한 단계와 없애도 되는 단계를 나누고, 새 흐름을 먼저 종이 위에서 설계합니다.

  3. 요구사항 정리

    새 흐름에 필요한 기능을 정리하고, 이미 쓰는 도구나 국산 SaaS로 해결되는지 확인합니다.
    해결되면 직접 개발하지 않습니다.

  4. 최소 기능으로 시험

    필요한 경우 작은 내부 도구나 자동화를 최소 기능으로 만들어 한 팀에서 먼저 써 봅니다.

  5. 사용 원칙과 정착

    AI 사용 원칙과 데이터 입력 규칙을 정하고, 담당자 교육과 점검 일정을 함께 정합니다.

06기대 산출물

  • DX 단계·AX 준비도 진단 결과
  • 병목 업무 분석
  • 재설계된 업무 흐름
  • 요구사항과 도구 선택 결과 (필요 시 MVP)
  • AI 사용 원칙과 데이터 입력 규칙

07적용의 전제와 한계

  • AI 도입 자체가 목적이 아닙니다.
    병목이 도구 없이 절차 정리만으로 해결되면 그렇게 권합니다.
  • 대규모 시스템 구축(ERP 전면 교체 등)은 전문 개발사와 함께 진행해야 하며, 이 경우에는 요구사항 정리와 검수 역할을 맡습니다.
  • 새 흐름이 정착하려면 담당자가 기존 방식을 내려놓는 기간이 필요합니다.
    한 번에 전사로 넓히기보다 한 팀에서 시작합니다.

08비슷한 사례

『경영전환론』에 실린 사례 가운데 이 문제와 닮은 것입니다.
회사와 사람을 보호하기 위해 익명화·재구성했습니다.

  • 식품 회사 · 출고 오류는 사람 탓이 아니었다
  • HR 솔루션 창업 · 조직을 키우지 않고, 규모를 키웠다

09먼저 해 볼 수 있는 자가진단

  • AX 준비도 진단
  • DX 단계 진단
  • CRM·고객관리 성숙도 진단
